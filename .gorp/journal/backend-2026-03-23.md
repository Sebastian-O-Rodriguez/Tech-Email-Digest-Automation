## Implementation Notes

**Exception hierarchy added (module-level, importable by callers):**
- `GraphAuthError` — 401 responses (expired/invalid token)
- `GraphPermissionError` — 403 responses (missing Mail.Read consent)
- `GraphThrottleError` — 429 responses; carries `retry_after: int | None` parsed from the `Retry-After` header
- `GraphAPIError` — all other non-2xx responses; carries `status_code` and `body` for diagnostics

**`_raise_for_graph_error(response)`** — centralised dispatch using a `match` statement; called instead of `response.raise_for_status()` so callers get typed, descriptive exceptions.

**`_parse_email` hardening:**
- Return type changed to `Email | None`
- Returns `None` + `logger.warning` for: missing `id`, missing `receivedDateTime`, unparseable `receivedDateTime`
- Uses `or` fallback on `subject` and `sender` to catch empty-string cases in addition to missing keys
- Guards `body.get("content")` behind `isinstance(body, dict)` to avoid AttributeError if Graph returns a non-dict

**`fetch_new_emails` hardening:**
- `response.raise_for_status()` replaced with `if not response.is_success: _raise_for_graph_error(response)`
- Tombstone objects (`"@removed" in msg`) are detected and silently skipped before calling `_parse_email`; Graph returns these during delta queries when messages are deleted
- `page_number` counter added; logged at each page fetch and in the final summary line
- Per-page `INFO` log: "Page N: received M message(s)."
- Pagination `INFO` log: "Pagination: fetching next page."
- Final `INFO` log: "Fetch complete. N new message(s) retrieved across P page(s)."
- Empty folder scenario: `value` is `[]`, loop body produces zero emails, returns `([], updated_state)` — no error

**Review findings — no logic bugs found:**
- `model_confidence` blending: `confidence_adj = model_confidence * 0.15` is additive on top of base priority score. Maximum contribution is `0.15` (when confidence is `1.0`), which is intentional and proportionate.
- Unknown priority: `_PRIORITY_SCORES.get(summary.priority, 0.1)` defaults to `0.1` (same as "low"). Added `logger.warning` for this branch since `Priority` is a `Literal` type — an unknown value indicates a contract violation upstream.

- Score clamping: `max(0.0, min(1.0, raw_score))` correctly constrains to `[0.0, 1.0]` before rounding. With maximum possible inputs (`base=1.0`, `link_adj=0.3`, `body_adj=0.05`, `confidence_adj=0.15`), raw max is `1.5`, clamped to `1.0`. With minimum inputs (`base=0.1`, `subject_adj=-0.05`, all others zero), raw min is `0.05`, stays positive.
